# Automatic cut-outs, opt-in per hub

## What to use for the cut-out
Two layers, cheapest first:

1. **White-background removal (main path, free, instant).** Our generated subject images sit on plain white. A small image routine running on our backend flood-fills the white from the picture's edges and makes it transparent, softening the border so there is no white halo. Because it only removes white connected to the edges, white parts inside the subject (teeth, eyes, a white shirt) stay intact. It gives the same result every time and costs no AI credits.
2. **AI fallback (only when needed).** If the edges aren't mostly plain white (a busy photo, a pushed-in picture with a real background), the image is sent to the built-in AI image editor (`openai/gpt-image-2.5-sunburst`) with a "remove the background, transparent PNG, keep the subject unchanged" request. This costs credits, so it only runs when step 1 can't.

Result check: if the cut-out ends up almost empty or almost unchanged, it is marked as failed with a reason, not saved as a bad file.

## How it behaves
- New hub setting **"Auto cut-outs"**, off by default. Toggle on the hub page (Style tab). Turned on for VOX collage by default; any other hub can turn it on.
- When an image is created in an opted-in hub — generated by `agent-create`, pushed by link, sent through `asset-ingest`, or uploaded in the browser — a cut-out starts in the background, right after the file is saved (same way the description does).
- The original stays. A second file appears in the same project (or library): `<name>-cutout.png`, tagged `cutout`, same role as the original, linked back to it. It has a normal permanent link for Remotion.
- While it's being made it shows as "creating" (link returns "try again shortly"); if it fails it shows the reason.
- Cut-outs are not cut-out again, and don't get their own description (saves credits).
- Hubs without the setting behave exactly as today.
- Manual "Make cut-out" button on image files as a re-run.

## Technical details
- Migration: `asset_groups.auto_cutout boolean not null default false`; set true for slug `vox`.
- New `supabase/functions/_shared/cutout.ts`: `startCutout(asset)` → checks hub flag, skips if tagged `cutout`, inserts placeholder asset (`meta.creating`, `meta.source_asset_id`, tags `['cutout']`), returns background job. Decode PNG/JPEG with `npm:imagescript`, edge flood-fill (tolerance ~ near-white, feathered alpha), encode PNG, upload to `hub-media`. Edge-whiteness below ~85% → gateway `/v1/images/edits` with `background: "transparent"`.
- Hook into `agent-create` (after `finish()` upload and sourceUrl path), `asset-ingest`, and a new small `make-cutout` function (called by browser upload and the manual button). `verify_jwt = false`.
- `project-manifest`/`group-manifest` expose `auto_cutout` and each cut-out's `source_asset_id`. Update `AGENT_ACCESS.md` and the make-vox skill to say "use the `cutout` file".
- Verify: push one image into `vox` and one into a non-opted hub; confirm two files vs one; confirm transparent corners in the PNG.
