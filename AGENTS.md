- Hubs = `asset_groups` rows; projects (`projects`) belong to a hub; assets with `project_id = null` are the hub library. Why: reuse existing tables, keep old links working.
- Colab video generation starts with the reproducible notebook generated by `scripts/create-ltx-notebook.py`; run `scripts/test-ltx-notebook.py` after changes and gate project integration on real GPU/full-clip validation. Why: structural checks cannot prove model fit, motion quality or free GPU availability.
- Human media search uses `media-search` with caller-scoped project access and server-only provider tokens; selected files use the regular browser upload path with source attribution. Why: reuse analysis/render-copy safeguards without exposing agent write credentials.
- Skills live in `skills` (group_id null = shared) and their source markdown in `/skills`; re-import with `bun ./scripts/import-skills.ts <repo-path>`. Why: one editable source agents can also read from GitHub.
- The `shared-library` hub is included in every project manifest. Why: cross-niche sounds/music without copying.
- Cut-outs: `_shared/cutout.ts` (edge flood-fill of white via deno.land imagescript, AI edit fallback), gated by `asset_groups.auto_cutout`; cut-outs are separate assets tagged `cutout` with `meta.source_asset_id`. Why: free, deterministic on generated white-background images; npm imagescript fails in the edge runtime.
- `render-video` strips `backdrop-filter` from code before sending it to Lambda. Why: Lambda Chrome renders without a GPU, so backdrop blur costs seconds per frame and renders time out.
- `render-video` resolves fps/frames itself (REMOTION_CONFIG → compositionConfig, arithmetic allowed) and prepends a plain-number `/* compositionConfig = {...} */` comment. Why: the S3 bundle reads the first compositionConfig with a digits-only regex, so `2015 / 30` seconds became 2015 seconds.
- Editor agent (`editor-agent` edge function, /groups/:slug/p/:project/editor) saves each code change as a new project `code` asset (`meta.source=editor`, `meta.version`) and edits via exact find/replace tools; chat is stored in `editor_messages`. Why: small edits are cheap and every version can be undone.
- Full video builds never stream code through the chat: `build_video` queues an `editor_builds` row and `editor-build` writes the file in background parts (each part self-invokes the next, resumable), sharing context via `_shared/editor-context.ts`. Why: long tool-call streams were cut off at ~58s and froze the chat.
- Style references are hub/shared library `text` assets with `role = style-reference` (card in inline_content, meta.source_code_asset_id); the editor agent lists them and loads them on request via read_style_reference. Why: reuse a look without a template, no new table.
- Model choice: UI list `src/lib/models.ts` must match `EDITOR_MODELS` (`pickModel`, default Astra); `openrouter/` ids use `OPENROUTER_API_KEY`; builds store `editor_builds.model` and keep part text last with a `promptCacheKey`. Why: users trade cost for quality, incl. own-account models, with cache reuse.
- Hub `analysis_mode` ('standard' | 'reaction') picks video analysis: reaction hubs get chunked `gemini-reaction` (timeline + reaction_moments); assets with role/tag `reference` get `gemini-edit-style`; both via `runReaction` in `_shared/analysis.ts`, shown in full to the editor. Why: reaction edits need a dense, timed picture of the source, and reference clips teach edit rhythm.
- Scripts are written only on request (editor "Create script" button) and saved by the `save_script` tool as project `text` assets with role `script`. Why: the user drives when scripting happens; versions are kept.
- Reusable characters are hub library `code` assets with `role = character`; the editor context includes their full code. Why: the agent copies one tested character instead of redrawing it each video.
- Lottie JSON files are `text` assets with `role = lottie` and `meta.lottie` (fps/frames/markers); preview and editor handoff use `src/features/hub/lottie.ts` native timing and `@remotion/lottie`, also in Lambda bundle. Why: reuse assets and preserve designer timing through export; ZIP-format .lottie archives are not supported.
- Heavy videos (>1920px long side or very high bitrate, non-`source` role) get a browser-made 1080p copy (`src/features/hub/render-copy.ts`, mediabunny) at `meta.render_path`; `asset-url` serves it by default (`part=original` for the upload) and `render-video` refuses while `meta.needs_render_copy` is unresolved. Why: 4K frames exhaust GPU-less Lambda memory/disk.
- Subdirectories have their own `AGENTS.md` (e.g. `src/features/clipping/`); read it before changing files there or clip handling in edge functions.
